# AGENTS.md: правила для всех ИИ-агентов проекта

Проект: онлайн-доска для уроков (Excalidraw, Cloudflare Workers, Durable Objects, D1).
Источник истины: `SPEC.md`. Если этот файл и `SPEC.md` противоречат друг другу, остановись и спроси владельца.

## Порядок работы

1. Прочитай `SPEC.md` целиком, затем свою задачу (промпт из `PROMPTS.md`).
2. Работай в отдельной ветке `task/T<номер>-<кратко>`. Один pull request на задачу.
3. Не расширяй задачу. Нашёл смежную проблему: запиши её в PR в разделе «Замечания вне задачи», не чини.
4. Контракт (разделы 5, 6, 9 в `SPEC.md`) не меняй без правки `SPEC.md` в том же PR и пометки `CONTRACT CHANGE` в заголовке PR.
5. Перед завершением запусти проверки и приложи вывод команд.

## Технические правила

- TypeScript в strict-режиме. `any` только с комментарием, почему иначе нельзя.
- Идентификаторы и комментарии в коде на английском, текст интерфейса на русском (все строки в `web/src/i18n/ru.ts`).
- Зависимости: только MIT, Apache-2.0, BSD-2-Clause, BSD-3-Clause, ISC. Нельзя: tldraw, любые GPL, AGPL, SSPL и «source-available» лицензии. Каждая новая зависимость перечислена в PR с лицензией и причиной. Зависимостей как можно меньше.
- Cloudflare: только бесплатные возможности. Лимиты в `SPEC.md`, разделы 3 и 8. Durable Object только с SQLite-хранилищем (`new_sqlite_classes`). R2 и платные функции не используем.
- Лимит записей строк: ничего не пиши в SQLite на каждое сообщение. Сброс снимка по `SAVE_INTERVAL_MS`, без вторичных индексов на горячих таблицах, `updated_at` в реестре не чаще раза в 10 минут. Помни: удаления и `setAlarm` тоже считаются записями.
- API платформ (Cloudflare, wrangler, Excalidraw) сверяй с актуальной документацией и исходниками в `node_modules`, а не с памятью. Не уверен в сигнатуре: прочитай исходник пакета.
- Секреты никогда не попадают в код, логи, тесты, PR и чаты. Только `.dev.vars` (в `.gitignore`), секреты GitHub Actions и секреты Worker. В репозитории только `.dev.vars.example`.
- Приватность: только ники. Никаких ФИО, контактов, сторонней аналитики, внешних шрифтов и CDN: все ресурсы из своего бандла.
- Тесты: у каждой функции есть тест или в PR описан ручной сценарий проверки. Не отключай и не ослабляй тесты ради зелёного CI.
- Коммиты маленькие, сообщения понятные, язык сообщений единый по всему репозиторию.

## Честность отчётов

- Пиши «работает» только после запуска. В PR есть раздел «Что проверено» (команды и результат) и «Что не проверено» (с причиной).
- Не выдумывай факты о платформах. Нет уверенности: пометь `ПРОВЕРИТЬ` и оставь вопрос в PR.
- Требование неясно: не угадывай. Выбери самый безопасный вариант, назови допущение явно и оставь вопрос в PR.

## Шаблон PR

Заголовок: `T<номер>: <кратко>`

- Что сделано
- Как проверить (команды)
- Что проверено / что не проверено
- Новые зависимости (имя, лицензия, зачем)
- Допущения и вопросы
- Замечания вне задачи

## Без явного разрешения владельца нельзя

Менять лицензии, добавлять платные сервисы, подключать внешние API, отправлять данные досок третьим сторонам, удалять данные, пушить напрямую в `main`.
